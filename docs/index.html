Площадка, где встречается вся производственная цепочка

Что внутри

Рабочий маркетплейс, а не макет

Шесть связанных сценариев: от регистрации компании до оплаты тарифа и внутренней переписки по заявке. Всё на реальных данных в базе, с ролями и проверкой прав.

Каталог компаний

15 отраслей-ролей в цепочке, поиск по названию и городу, фильтры, сортировка, пагинация, рейтинг и отзывы.

Заявки и отклики

Потребность с бюджетом и сроком, отклики с ценой, принятие предложения и статусы «открыта / в работе / закрыта».

Переписка по заявке

Диалог открывается откликом и привязан к паре «заявка + компания». Сообщения видят только две стороны.

Тарифы и продвижение

Базовый, PRO и Premium: приоритет в каталоге, бейдж в карточке, история платежей и автоматическое снятие по сроку.

Логотипы и документы

Загрузка логотипа вместо монограммы, приватные документы компании, раздача файлов через resource handler.

Кабинет и админка

Профиль, предложения, заявки, отклики, избранное; модерация компаний и статистика площадки для администратора.

Этап 1 · реализовано

От частного лица к юридическому статусу

Владелец актива приходит без компании: выбирает юрфирму рядом, подаёт заявку, согласует очную явку и платит через эскроу. Деньги уходят исполнителю только после того, как заказчик передаст одноразовый код.

Как проходит сценарий

  1. Регистрация как частное лицо — без юридического статуса.
  2. Каталог юруслуг: расстояние до фирмы, рейтинг, отзывы и платное продвижение.
  3. Заявка: будущая компания, город, отрасль, комплект документов.
  4. Юрфирма запрашивает документы и назначает очную явку.
  5. Оплата в эскроу — деньги удерживаются на площадке.
  6. Услуга оказана: заказчик получает код и передаёт его исполнителю.
  7. Код подтверждён — платёж выплачен, аккаунт становится юрлицом с готовой карточкой компании.
Интерфейс

Экраны приложения

Собственная дизайн-система: светлая «бумажная» база, графитовые панели, лаймовая подсветка действий и моноширинные технические подписи. Адаптив до 390 px.

Как устроено

Стек и архитектура

Классические слои Spring: домен → репозитории → сервисы → REST-контроллеры → SPA. Без Spring Security и Thymeleaf — сборка идёт из локального кэша Maven.

Сервер

  • Java 21, Spring Boot 3.2.2, Spring MVC
  • Spring Data JPA, Hibernate 6.4, H2 (профиль PostgreSQL)
  • Сессии + PBKDF2-HMAC-SHA256, роли ADMIN, PERSON, COMPANY
  • Эскроу-леджер: удержание → одноразовый код → выплата или возврат
  • Расстояние между городами по координатам, без внешних гео-сервисов
  • Планировщик снятия истёкших тарифов
  • 27 тестов: JUnit 5, AssertJ, MockMvc

Клиент

  • SPA на ES-модулях: hash-роутер, свой fetch-слой
  • Собственная CSS-дизайн-система, без npm и сборки
  • Страницы: главная, каталог, компания, заявки, заявка, чат, кабинет, админка
  • Загрузка логотипа и документов, предпросмотр, валидация форм
  • Адаптив: десктоп 1440 px и мобильные 390 px
Запуск

Поднять локально

Нужны JDK 21 и Maven. База H2 создаётся сама, демо-данные загружаются при первом запуске.

Windows, одной командой

git clone https://github.com/Bell-igor/proAX.git
cd proAX
.\run.cmd

Приложение откроется на http://127.0.0.1:8080

Любая ОС, через Maven

mvn clean package
java -jar target/proax.jar
